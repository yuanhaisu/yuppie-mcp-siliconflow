# 合并设计说明

本仓库把两个来源合并为一个 Python 双包 MCP 项目。

## 来源

1. **`lioensky/siliconflow-flux-mcp-server`**（TypeScript，本机 `siliconflow-flux-mcp-server` 仓库）
   - `generate_image` 工具：`prompt` + `resolution` 枚举 + `seed`
   - 返回 HTML `<img>` 标签，由模型补 `width` 后直接展示（**本仓库已弃用该形态**，见下方「合并取舍」）
   - 默认模型 `Tongyi-MAI/Z-Image-Turbo`，规避 FLUX.1-schnell/dev 的 S3 签名 403 坑
2. **`stevefordev/siliconflow-mcp`**（Python，已发布 PyPI）
   - 更全的能力面：图像/视频/语音、`aspect_ratio`、`negative_prompt`、`batch_size`、
     `output_format`、`edit_image`、`list_models`、`get_user_info`、本地保存
   - 结构上是一个 `FastMCP` 单包

## 合并取舍

| 维度 | 取值 | 来源 |
|------|------|------|
| 默认文生图模型 | `Tongyi-MAI/Z-Image-Turbo` | TS 版（规避签名坑） |
| 输出形态 | 原生 MCP `ImageContent` 图片块 + 文本摘要 | 本仓库自研（弃用 TS 版的 HTML `<img>`） |
| 分辨率 | 显式枚举，兼容宽高比映射 | 两者融合 |
| 能力面 | 文生图 / 图生图（见「范围收敛」） | Python 版，后经收敛 |
| 本地保存 | `SILICONFLOW_IMAGE_DIR` | Python 版 |
| Base URL | `https://api.siliconflow.com`（国际站，可用环境变量切换） | 两者一致 |
| 包结构 | uv workspace 双包（库包 + MCP 壳包） | 本仓库既有规范 |
| MCP 框架 | `mcp.server.mcpserver.MCPServer`（非 FastMCP） | 本仓库既有规范 |

### 为什么弃用 HTML `<img>` 形态

TS 版把结果拼成一段含 `<img src="...">` 的 markdown，依赖**客户端前端**去渲染原始 HTML。
实测在 Cherry Studio 里会显示为破图（只剩 alt 文案）：S3 预签名 URL 本身有效
（`curl` 200 / 真 PNG），但 raw HTML `<img>` 的 `src` 过不了前端的 sanitize 管线。
该形态还有两个隐患：临时签名 URL **24 小时过期**；模型要**逐字转写 ~1500 字符的签名串**，
错一个字符即 `SignatureDoesNotMatch`（签名从头无效，重试无用）。

改为：**服务端下载图片字节，工具返回原生 `ImageContent` 块**（文本摘要 + 图片块），
由客户端原生组件渲染，不经过 markdown/HTML sanitizer，也不依赖外链。

- 返回形态由 `server.py` 把 `tools/images.ImageToolResult` 转成
  `list[TextContent | Image]`；测试断言 `mimeType == "image/png"`
  —— S3 常回 `application/octet-stream`，客户端靠 mimeType 决定渲不渲染。
- 取字节用**裸** httpx client（不带 `Authorization`）：S3 只允许一种鉴权机制，
  与 URL 里的 `X-Amz-*` 同时出现会 403。

## 结构

```
packages/yuppie-siliconflow        # 库包（httpx，无 mcp 依赖）
  config.py    # SiliconFlowConfig.from_env()，内置 .env 加载
  base.py      # httpx client、统一请求、SiliconFlowError
  files.py     # 下载/落盘
  images.py    # generate_image / edit_image（mixin）
               # + ASPECT_RATIOS / MODEL_ASPECT_SIZES / resolve_image_size
packages/yuppie-mcp-siliconflow    # MCP 壳包（依赖库包 + mcp + pydantic）
  tools/*.py   # 纯 async 实现 + Pydantic 入参模型
  server.py    # 唯一 import mcp 的文件，注册 2 个工具
```

## 范围收敛

合并初期照搬了 Python 版的全部能力面，之后按实际使用收敛为**只要文生图与图生图两个工具**，
签名对齐 [`stevefordev/siliconflow-mcp`](https://github.com/stevefordev/siliconflow-mcp)：

| 时间 | 变更 | 原因 |
|------|------|------|
| 2026-08-14 起 | 移除 `get_user_info` | 上游 `/v1/user/info` 永久下线（HTTP 410），无替代接口 |
| 2026-10-13 | 移除文生视频（`videos.py` + 3 个工具） | 未使用，收敛范围 |
| 2026-10-13 | 移除语音合成（`audio.py` + 1 个工具） | 同上，连带移除 `SILICONFLOW_AUDIO_DIR` |
| 2026-10-13 | 移除模型列表（`account.py` + `list_models` 工具） | 同上；库包 `AccountMixin` 随之删除 |
| 2026-10-13 | 默认编辑模型改为 `Qwen/Qwen-Image-Edit` | 原 `-2509` 后缀不在官方文档列出的模型 ID 中 |
| 2026-10-13 | 参数名对齐参考仓库 | `resolution` → `image_size`、`batch_size` → `num_images` |

收敛后 MCP 工具数：8 → 7 → 3 → **2**（`generate_image` / `edit_image`）。

## 按模型的分辨率

各模型的尺寸档位差异很大（Z-Image 是 512 档、Qwen-Image 是 1328 档、Ultra/dev 是 1024 档），
用一张全局表会把模型不认识的尺寸发出去。因此 `images.py` 里的 `MODEL_ASPECT_SIZES` 按模型
分别给出「比例 → 尺寸」映射，未收录的模型回退到通用表 `ASPECT_RATIOS`。

默认值保留本仓库的 `Tongyi-MAI/Z-Image-Turbo`，**未采用参考仓库的 `FLUX.1-schnell`**
—— 后者在硅基流动返回的 S3 预签名 URL 签名无效（403），是本仓库已记录的坑。

## 拆分动机

只想调用硅基流动 API 的 Python 用户，不必被迫安装 `mcp>=2.0.0,<3.0.0`
（避免与其自身项目的 MCP 版本冲突）。
